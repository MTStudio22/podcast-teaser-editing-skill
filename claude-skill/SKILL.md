# Podcast Teaser Editing

This skill encodes a tested protocol for cutting a long-form podcast into a short trailer/teaser (the style used by Diary of a CEO, Editing Explained, and similar high-performing podcast channels). Apply it whenever asked to plan a teaser edit, build a cut-list/script from a podcast transcript, or review/critique an existing teaser draft.

## 3 foundational rules (apply to every decision)

1. **Cut for the avatar, not the ego.** Every clip choice is filtered through the target viewer's profile, never the editor's personal taste. Before anything else, profile the avatar in 5 questions: who are they, what do they do, their income/budget level, what they're here to learn/get, and what stage of that journey they're at.
2. **Context over clutter.** Fewer, well-chosen clips that build real context beat a pile of "this looked interesting" cuts. Every numeric cap below exists to enforce this rule — when unsure whether to keep a clip, ask whether cutting it costs context or is just clutter under a different marker's name.
3. **Provoke emotion.** The cut should land an emotional beat for that specific avatar — via a relatable pain point, a rhythm break (sudden silence), a bold claim, etc. — not just be "interesting."

## The 6 markers and their math

| Marker | Rule |
| --- | --- |
| **Time** | 1hr–1h45m source podcast → trailer length 1:10–1:30. 2hr+ source → only 50s–1:10 (shorter, not longer — viewers who click a 2hr+ video are already high-intent and don't need convincing). No validated numbers exist for sources under 1hr or in the 1h45m–2hr gap — treat those as extrapolated, not proven, and say so if used. |
| **Music** | Cinematic violin is the best-validated default instrument. BPM: 100 when the speaker's energy is already high; 150–190 to enhance when energy is lower. Switch instrument/BPM per segment as context/energy shifts — ideally syncing a switch to a pattern interrupt. Test variations rather than copying blindly. |
| **Pattern interrupts** | Minimum 1, max 2 for sustained audience quality (some podcasts run higher, not recommended for retention). 1 interrupt → place at 45–55% of trailer length. 2 interrupts → first at ~30%, second at ~80%. |
| **Questions** | Cap at ~30% of total statement weight. A question that resolves into a statement mid-sentence doesn't count toward the ratio. |
| **Bold statements** | <1 min trailer → 7–9 statements. 1–1:40 trailer → 10–13 max, never more (going past this breaks Rule 2). |
| **Ending bridge** | The final ~15 seconds matter as much as the first 15. Must land exactly ONE (never mixed) of: (a) **status upgrade/ego hit** — elevate or challenge the viewer's identity; (b) **perceived value** — imply outsized value just given ("I should've charged $500 for this"); (c) **authority with proof** — a credibility claim backed by evidence, not a bare assertion. Pick the type based on the avatar: skeptical/price-sensitive → authority-with-proof; already sold on the topic → status-upgrade; curious-but-undecided → perceived value. |

**Key synthesis point:** markers stack on the same clips rather than each getting a separate slot. The total statement budget (10–13, or 7–9 under a minute) is the real governing constraint — pattern interrupts and the ending bridge usually land ON a clip already counted as a bold statement or question, not as additions to the count. When selecting clips, prioritize ones that can serve 2+ markers at once.

## Editing protocol (in order)

1. Build a timeline, drop the full raw podcast on it.
2. Watch the entire raw podcast once, calmly, start to finish — no scrubbing, no fast-forward.
3. Mark every candidate moment with color-coded markers: green = certain fit (avatar + a rule, will use), orange = backup/maybe (use only if the statement quota isn't otherwise met), red = questions (tracked separately against the 30% cap).
4. For each marked clip, check whether it can serve 2+ markers at once — those are the highest-priority picks.
5. Duplicate the timeline ("stacked timelines") so the original marked timeline stays untouched as reference; never cut directly into it.
6. On the new timeline, pull marked clips up and arrange for pacing.
7. Place pattern interrupt(s) per the ratio above.
8. Lay in music per the BPM lane decided from speaker energy; switch tracks where energy/context shifts.
9. Build the ending bridge in the final ~15 seconds using the single bridge type chosen for this avatar.
10. Confirm the final 15 seconds got as much attention as the first 15 (the opening hook).

## Final quality gate (check before calling a cut-list/script done)

- [ ] Trailer length matches the Time band for the source runtime
- [ ] Total bold-statement count is within the band for that trailer length
- [ ] Questions are ≤30% of total statement weight
- [ ] 1–2 pattern interrupts present, correctly placed
- [ ] Exactly one ending-bridge type present in the final ~15s, matched to the avatar
- [ ] Every clip passes "does cutting this cost context, or is it clutter" — no ego-driven inclusions
- [ ] Music matches the BPM lane; no unmotivated switch

## Deliverable formats

When asked to apply this to a specific podcast transcript, offer (or produce, if already specified) one or more of:
- **Cut-list/edit blueprint**: timestamped selections mapped to each marker (time budget, bold statements, questions, pattern-interrupt placement, music cues, ending-bridge choice)
- **Full sequenced trailer script**: exact lines/timestamps in final assembly order, with inline music + marker notes
- **Standalone markup**: the raw transcript annotated with candidate bold statements, pattern-interrupt moments, and emotional beats, left for the user to sequence themselves

Always ask the user's avatar profile first if it isn't already known — it's the filter every other step runs through.
